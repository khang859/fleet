## Async folder creation can overwrite a newer config choice

A temporary component check started an edit from `/configs/old` to `/configs/new`, held `ensureConfigDir` pending, then selected Use default. The override was removed successfully. Completing the earlier directory request then restored `/configs/new`, overriding the newer user choice.

The new filesystem await occurs before `setWorkspaceOverride`, without serialization or a check that the request is still current. Keep workspace config operations ordered, or invalidate superseded operations before they persist their result. This fix remains outstanding.

## An empty Custom selection silently becomes Default

A temporary component check created a workspace named `研究` and selected Use custom folder. The ASCII-only slug generator produced no suggested folder, but Create remained enabled. Submission succeeded without creating a config directory or writing an override, because an empty custom value is converted to null.

Require a nonempty path when Custom is selected and prompt for one when a suggestion is unavailable. Clearing a suggested path should likewise require an explicit choice of Default rather than silently changing the selected mode. This fix remains outstanding.

## Verification at 73cb8e67

The empty-Custom validation is fixed, including the no-suggestion case for a non-Latin name. The original stale-request reproduction (an existing custom workspace changed to another folder, then Default) also passes with the new request counter.

The stale-request fix is incomplete when the newest choice matches persisted state. Two component checks reproduced it:

- An inherited workspace starts a custom-folder request. While directory creation is pending, selecting Custom then Default does not call `setOverride`, because `isCustom` still describes the persisted default. The request counter is not advanced and the pending path later becomes the override.
- A custom workspace starts a request for a different path, then the user enters its original saved path. `commitCustom` returns early for equality with the saved path, again leaving the old request current.

Invalidate pending operations for every explicit committed choice, including choices that require no persisted change. Otherwise treating a write as a no-op also incorrectly treats cancellation of the pending write as a no-op. This remaining case was reported for review; no application fix was applied.
